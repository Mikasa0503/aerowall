# 上游循环策略接入前检查

按实施计划，先检查固定 JuggleRL 上游的 PPO/RNN 路径，再决定项目内最小适配。CPU 探针 `scripts/probe_upstream_gru.py` 已运行，结果保存为 `upstream-gru-audit.json`。

确认的问题：

- GRU 实现包含 `LayerNorm(output + input)` 残差。256 维编码输出配合配置注释中的 128 维隐藏状态会直接维度报错。256/256 等宽设置可运行。
- 启用 actor GRU 且输出分布参数时，配置生成 6 个输出键，但循环 actor 的 rollout 返回 7 项，包含隐藏状态前额外的 `None`。因此直接打开配置不足以得到正确的循环策略数据接口。

已通过的模块级检查：等宽 GRU 的整段输出与逐步输出一致，最终隐藏状态一致，选定 episode 重置点的输出与清零历史后重新计算一致。

探针直接载入固定上游 GRU 文件，并从上游 AST 提取原始 Actor 与分布类型判断函数执行，避免加载仿真包；仅提供所需依赖和简单测试分布。检查对象与源码哈希均保存在报告中，没有改动上游文件。

下一步需要项目内适配返回协议，并验证收集器跨步携带隐藏状态、选择性重置、训练序列初始状态、共享 actor 的序列 minibatch 与 checkpoint 重载。当前 **不能声称 GRU-PPO 已接入或可训练**，也没有完成三方法公平比较。壁球 FF 课程仍在开发，循环方法正式训练须使用后续冻结的同一课程和预算。
