# 单机 HCSP 壁球适配定义

该实验是公开完整 HCSP 控制器的单机适配，不是原始六机系统的无改动迁移，也不是仅抽取一个低层技能。全部 26 个低层角色实例和双方高层 actor 保持加载、调用；实际场景每环境只有 1 个 IrisTest articulation。

## 输入与动作

- 己方 FirstPass / SecPass / Att 三个角色读取同一物理无人机状态。
- 对方三个状态槽用该状态关于原球场中心旋转 180 度的占位值补齐。占位没有物理实体，也不接触球。该输入分布不同于训练分布，是明确的适配假设。
- 原高层仍输出三角色技能选择，原低层仍输出各技能动作。先经过原环境技能选择，单机仲裁在击球技能同时被选中时采用 FirstPass > SecPass > Att；无击球角色时执行 FirstPass 当前动作。发球阶段固定选 FirstPass。
- 这是首个可审计映射，不声称它是最优或训练时已有的功能。后续对照须记录实际角色、动作和高层输出，不能把仲裁失败归因于原技能不能迁移。

## 场景与回合

- 实体墙中心 `[0,0,4]`、尺寸 `[0.2,8,8]`、恢复系数 0.8；球与机始于 x>0.1 的同一侧。
- 使用原始近侧发球位置分布；单机初始四元数为单位、速度为零。此初始化简化单独记录。
- 球/机状态只在回合 reset 设置，回合中由 PhysX 推进。
- 墙反弹后结束发球阶段、清空原角色的 already_hit 标记，允许同机再次处理来球。原排球的过网、错方击球规则不适用于壁球，替换为落地/场界/超时终止。
- GPU contact filter 分别读取球—唯一机体、球—墙冲量。成功候选是机体接触→墙接触→同机接触，连续接触去重，同时触墙/机体事件不计成功。
- 机体接触不自动等于合法球拍顶部触球。首轮结果必须注明这一限制，后续审计需要接触位置/法向。

## 禁止的替代

不能用虚拟槽位当作物理队友；不能用三机接力当作单机成绩；不能瞬移球制造回球；不能通过随机填充高层输出权重宣称已加载完整策略；不能把当前适配失败作为 HCSP 不具备可迁移技能的证明。
